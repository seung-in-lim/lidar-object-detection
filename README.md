# LiDAR 포인트클라우드 기반 장애물 검출

> **3D LiDAR Point Cloud Obstacle Detection** > **KITTI 데이터셋 / 고전적(non-deep-learning) 클러스터링 파이프라인**

---

## 1. 프로젝트 개요

KITTI 자율주행 데이터셋의 **3D LiDAR 포인트클라우드**를 입력으로, 도로 위 장애물(차량·구조물 등)을 검출하는 인지(Perception) 파이프라인을 구현했습니다.

별도의 LiDAR 장비 없이 **공개 데이터셋과 노트북 한 대만으로**, 라이다 원본 점군을 받아 지면을 제거하고 장애물을 개별 물체로 분리한 뒤 바운딩 박스로 검출하는 전 과정을 설계 및 학습했습니다.

이 프로젝트는 선행 프로젝트(자율주행 경진대회)에서 **카메라 기반 인지**를 다룬 경험에 이어, 자율주행 인지의 또 다른 핵심 센서인 **LiDAR(3D 포인트클라우드)** 를 직접 다뤄보기 위해 진행하였습니다.

> 🔗 선행 프로젝트: [autonomous-driving-competition](https://github.com/seung-in-lim/autonomous-driving-competition)

---

## 2. 동기

선행 자율주행 경진대회 프로젝트의 회고에서, 다음에 도전해보고 싶은 방향으로 **"LiDAR 기반 인지"** 와 **"카메라 외 센서 활용"** 을 꼽았습니다. 당시 카메라·초음파만으로는 위치 및 주변 인식에 한계가 있음을 체감했기 때문입니다.

본 프로젝트는 그 연장선에서, 카메라(2D 이미지)가 아닌 **LiDAR(3D 포인트클라우드)** 로 주변 환경을 인식하면 어떻게 다른지를 직접 경험하기 위해 시작했습니다. 이를 통해 자율주행 인지의 **양대 센서(카메라 / LiDAR)** 를 모두 다뤄본 경험을 갖추는 것을 목표로 했습니다.

---

## 3. 사용 데이터

- **데이터셋**: KITTI 3D Object Detection (Velodyne LiDAR)
- **형식**: `.bin` 바이너리 (포인트당 x, y, z, intensity 4개 값)
- **규모**: 학습셋 7,481 프레임 (프레임당 약 10만 점)
- **좌표계**: 차량 기준 (x: 전방, y: 좌측, z: 상방)

> LiDAR 원본 데이터는 용량이 크므로 본 저장소에는 포함하지 않았습니다.
> 데이터는 공개된 KITTI 3D Object Detection 데이터셋(Kaggle 등)에서 받을 수 있습니다.

## 4. 시스템 파이프라인

전체 검출 시스템은 **로딩 → 지면 제거 → 클러스터링 → 바운딩 박스 + 후처리**의 단계로 구성됩니다.

```
LiDAR (.bin)
   │
   ▼
[1] 포인트클라우드 로딩        load_pointcloud.py
   │
   ▼
[2] RANSAC 지면 제거          ground_removal.py
   │   (도로 평면 추정 후 제거 → 장애물 점만 남김)
   ▼
[3] DBSCAN 클러스터링         clustering.py
   │   (가까운 점끼리 묶어 개별 물체로 분리)
   ▼
[4] 바운딩 박스 + 후처리 필터  detection.py
   │   (크기 / 높이 / 형상 필터로 오검출 제거)
   ▼
검출 결과 (Bounding Boxes)
```

## 5. 핵심 모듈 상세 분석

각 단계가 어떤 알고리즘으로 동작하는지, 그리고 파라미터를 어떤 근거로 선택했는지 정리했습니다.

### 5.1 RANSAC 지면 제거 (Ground Removal)

라이다 점군에서 가장 많은 점이 포함되는 하나의 평면을 찾으면 그것이 도로 바닥입니다. 그 평면 근처의 점들을 지면으로 분류해 제거하면, 위로 솟은 장애물 점들만 남습니다.

**핵심 파라미터 `distance_threshold` 튜닝**: 평면으로부터 이 거리(m) 이내의 점을 지면으로 간주합니다. 0.15 / 0.2 / 0.3을 비교한 결과:

| threshold | 지면 비율 | 특징 |
|:---:|:---:|---|
| 0.15m | 50.2% | 지면이 다소 덜 걷힘 |
| **0.2m** | **54.8%** | **균형 (채택)** |
| 0.3m | 60.0% | 장애물 발밑까지 지면에 흡수 |

너무 크면 장애물 일부가 지면으로 흡수되고, 너무 작으면 지면이 덜 걷힙니다. 장애물 점을 충분히 보존하면서 지면을 깔끔히 제거하는 **0.2m**를 채택했습니다.

### 5.2 DBSCAN 클러스터링 (Clustering)

지면을 제거한 장애물 점들을, 가까이 모인 덩어리끼리 묶어 개별 물체로 분리합니다. 어떤 점 주변 `eps`(m) 거리 안에 `min_points`개 이상의 점이 있으면 같은 물체로 간주합니다.

**파라미터 튜닝 (eps, min_points)**: (0.5, 10) / (0.8, 15) / (1.0, 20)을 비교했습니다.

| (eps, min_pts) | 군집 수 | 특징 |
|:---:|:---:|---|
| (0.5, 10) | 263 | 과분할 (벽이 여러 조각으로 쪼개짐) |
| **(0.8, 15)** | **158** | **균형 (채택)** |
| (1.0, 20) | 119 | 과병합 경향 |

eps가 작으면 한 물체가 여러 조각으로 쪼개지고(과분할), 크면 인접한 두 물체가 합쳐집니다(과병합). 벽 같은 구조물은 하나로 묶이면서 개별 차량도 분리되는 균형점인 **(0.8, 15)** 를 채택했습니다.

### 5.3 바운딩 박스 + 후처리 필터 (Detection)

클러스터링 결과를 그대로 쓰면 두 가지 오검출이 발생합니다. (1) 지면에서 안 걷힌 잔여물, (2) 건물 벽 같은 구조물. 이를 줄이기 위해 물체의 **물리적 사전지식을 반영한 세 가지 필터**를 설계했습니다.

| 필터 | 기준 | 제거 대상 |
|---|---|---|
| 크기 필터 | 가로·세로 0.3~8m | 너무 작거나 큰 군집 |
| 높이 필터 | 높이 ≥ 0.4m | 납작한 지면 잔여물 |
| 형상 필터 | 종횡비 ≤ 5 | 한 방향으로만 긴 벽 |

**필터별 효과 (프레임 000010 기준)**: 158개 군집 중 — 크기 필터 20개, **높이 필터 43개**, 형상 필터 4개를 제외하여 최종 **91개** 물체를 검출했습니다. 특히 높이 필터가 차량 주변 지면 잔여물 오검출을 가장 많이(43개) 제거했습니다.

pip install -r requirements.txt

# 라이다 한 프레임에 검출 파이프라인 실행 + 결과 저장
python src/pipeline.py path/to/000010.bin --save results/detection.png

python src/pipeline.py path/to/000010.bin --ground_threshold 0.2 --eps 0.8 --min_points 15

## 9. 기술적으로 학습한 내용

- **3D 포인트클라우드 데이터 구조**: `.bin` 형식, (x, y, z, intensity) 구성, 차량 기준 좌표계
- **LiDAR 센서 특성**: 거리에 따른 점 밀도 변화(가까울수록 촘촘, 멀수록 듬성), 동심원 스캔 패턴
- **RANSAC 평면 추정**: 점군에서 지면 평면을 찾아 분리하는 원리와 임계값의 영향
- **DBSCAN 밀도 기반 클러스터링**: eps·min_points의 과분할/과병합 trade-off
- **후처리 설계**: 물리적 사전지식(크기·높이·형상)을 활용한 오검출 제거
- **Open3D 라이브러리** 활용한 포인트클라우드 처리 및 시각화

## 10. 한계 및 향후 발전 방향

### 한계
- **단일 프레임 검출**: 사용한 KITTI 3D Object Detection 데이터셋은 프레임이 연속이 아니어서, 프레임 간 물체 추적(tracking)은 구현하지 못했습니다.
- **고전적 방법**: 딥러닝 3D 검출(PointPillars 등)이 아닌 기하학적 방법을 사용했습니다. 
- **먼 거리 한계**: 라이다 점 밀도가 낮은 원거리 물체는 검출이 어려운 한계가 있습니다.

### 향후 발전 방향
- **다중 객체 추적 (MOT)**: KITTI Tracking 데이터셋의 연속 프레임으로 확장하여, 프레임 간 물체를 매칭하고 궤적을 추정
- **딥러닝 기반 3D 검출**: PointPillars, PointNet 등으로 확장하여 고전적 방법과 성능 비교
- **카메라-LiDAR 센서 퓨전**: 선행 프로젝트의 카메라 인지와 본 프로젝트의 LiDAR 인지를 결합한 융합 인지
